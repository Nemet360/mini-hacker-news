## Specification

Branch `milestone/m10-postgres`. Tag `v0.10.0`. Gate: line >= 90%; the integration suite moves to Testcontainers PostgreSQL and SQLite is dropped from it (D.2.3).

**10.1** `feat(data): select database provider by configuration`
- Changes: `Npgsql.EntityFrameworkCore.PostgreSQL`; `Database:Provider = Sqlite|Postgres`; the SQLite `Migrations/` folder deleted and `InitialCreate` regenerated against PostgreSQL (A.1.2); the `Database:Provider` switch stays only until the SQLite branch is deleted.
- Test: `Provider_setting_selects_matching_database_provider`. Accept: app starts under each setting.

**10.2** `build(docker): add docker-compose with PostgreSQL 16`
- Changes: `docker-compose.yml` (`postgres:16-alpine`, named volume, healthcheck), `.env.example` (no real secrets).
- Test: `scripts/compose-smoke.sh` waits for healthy and runs `pg_isready`. Accept: `docker compose up -d` healthy.

**10.3** `feat(migrations): generate Postgres migrations and map types`
- Changes: initial Postgres migration for the full schema; `timestamptz` for dates, `bigint` identity (`GENERATED BY DEFAULT AS IDENTITY`, so seeded test rows may supply their own ids - A.5.2), `text` content with A.5.5's `CHECK (char_length(content) BETWEEN 1 AND 10000)` (PostgreSQL's spelling of the SQLite constraint shipped in M1), case-insensitive unique index on username via `lower(username)`.
- Test: `Postgres_migration_applies_and_matches_model` (`has-pending-model-changes` per provider in CI).
- Accept: `\d posts` in `psql` matches the data-model section.

**10.4** `test(data): run integration suite against PostgreSQL`
- Changes: the integration suite moves to PostgreSQL only (D.2.3 — a second provider is a second set of behaviours to be wrong about); CI uses the service container through `TEST_PG_CONNECTION`, local runs fall back to `Testcontainers.PostgreSql`; each test class gets its own schema via `Respawn`.
- Test: the existing integration tests, now against PostgreSQL. Accept: the suite is green on PostgreSQL and no test references SQLite.

**10.5** `feat(config): make PostgreSQL the only provider`
- Changes: A.1.2 and D.5.2 both state the P1 data is dev data and is discarded, so there is no copy tool: the SQLite connection string, provider switch and `Database:Provider = Sqlite` branch are deleted, and startup fails with a clear message if no PostgreSQL connection string is present.
- Test: `Startup_without_postgres_fails_fast_with_a_named_message`, `No_sqlite_package_remains_in_the_dependency_graph`. Accept: `dotnet run` with the connection string unset explains itself in one line.
